Section 9: Serverless Compute.

Serverless compute means you deploy your application without managing the underlying servers. Google Cloud Platform offers several serverless options, and choosing the right one depends on what you're deploying, how it's triggered, and whether you need it to scale down to zero when idle. Let's walk through four serverless options side by side, and then discuss when to use each one.

The first option is Cloud Run. Cloud Run takes a container as its unit of deployment. It can be triggered by HTTP requests or messages from Pub/Sub. It supports scale to zero, meaning when no requests are coming in, it shuts down completely and you pay nothing. Cloud Run can run any Linux 64-bit container, giving you maximum flexibility over your runtime environment. Billing is per 100 milliseconds of request processing time. Under the hood, Cloud Run is built on Knative, which is an open-source Kubernetes-based framework.

The second option is Cloud Run Functions, which is Google's function-as-a-service offering. The unit of deployment here is a single function rather than a full container. It's triggered by events or HTTP requests and also scales to zero. Supported runtimes include Node.js, Python, Go, Java, .NET, Ruby, and PHP. Like Cloud Run, billing is per 100 milliseconds of execution time.

The third option is App Engine Standard. App Engine Standard deploys a full application and is triggered by HTTP. It also supports scale to zero. However, it uses fixed, pre-defined runtimes rather than arbitrary containers. Billing is per instance-hour, meaning you're charged for the time an instance is alive rather than per individual request. App Engine Standard runs on Google's proprietary sandbox environment.

The fourth option is App Engine Flexible. App Engine Flexible is similar to Standard but runs your application inside a Docker container on Compute Engine virtual machines. This means you can use any runtime you want. However, it does not scale to zero, so there will always be at least one instance running. Billing is per instance-hour, just like App Engine Standard.

Now let's look at how to choose between all the compute options available on Google Cloud, including non-serverless ones. If you have a full containerized web application, Cloud Run is your best choice. If you need an event-triggered, single-purpose function, use Cloud Run Functions. If you have a simple web application and want Google to manage the runtime for you, App Engine Standard is a great fit. If you need a custom runtime but don't need scale to zero, App Engine Flexible is the right option. If you need full operating system control and have persistent, long-running workloads, Compute Engine gives you that control. And if you need to orchestrate many containers at scale with fine-grained configuration, GKE, which stands for Google Kubernetes Engine, is the appropriate tool.
