Section 11: Monitoring and Observability.

Observability is the practice of understanding what your systems are doing by examining the data they produce. In the world of site reliability engineering, there is a well-established framework called the Four Golden Signals, and understanding these signals is the starting point for any serious monitoring strategy.

The first golden signal is Latency, which measures the time it takes your system to return a result. Latency matters because changes in latency, even subtle ones, often indicate that a problem is beginning to emerge before it becomes a full outage. The second golden signal is Traffic, which measures the volume of requests your system is handling. Traffic data gives you a baseline for capacity planning and helps you understand whether a performance issue is load-related. The third golden signal is Saturation, which measures how full a given resource is, such as CPU utilization, memory consumption, or disk capacity. High saturation is a warning sign that a resource is about to run out, and it often predicts imminent failure. The fourth golden signal is Errors, which measures the rate of failed requests. This is the most direct indicator of user impact, because users experience errors immediately.

Now let's look at the Google Cloud Platform products that support observability. There are five key products to know. First, Cloud Monitoring is the core service for working with metrics. It provides dashboards, uptime checks, and alerting, and it ingests data automatically from over 100 Google Cloud services, giving you more than 1,500 built-in metrics at no charge. Second, Cloud Logging handles the collection, routing, storage, and querying of log data. We'll cover Cloud Logging in detail in the next section. Third, Cloud Trace is a distributed tracing service that helps you find latency bottlenecks by tracking requests as they travel across the components of your application. Fourth, Cloud Profiler performs continuous CPU and memory profiling on your production workloads, helping you find inefficiencies in your code without having to reproduce issues in a test environment. Fifth, Error Reporting automatically groups similar errors together and sends alerts when new error patterns are detected, saving you from manually sifting through logs to find issues.

Let's go a bit deeper on Cloud Monitoring. Beyond the 1,500 or more metrics ingested automatically from Google Cloud services, Compute Engine provides over 25 additional unique metrics per virtual machine instance. To collect metrics and logs from processes running inside a virtual machine, or from third-party applications, you install the Ops Agent on the VM. For teams running Kubernetes workloads on GKE, which stands for Google Kubernetes Engine, Google Managed Prometheus provides built-in Prometheus-compatible monitoring support, so you can use familiar Prometheus tooling without managing the backend infrastructure yourself. Cloud Monitoring also supports uptime checks, which verify that your endpoints are reachable from multiple locations around the globe, ensuring you catch regional outages quickly.
